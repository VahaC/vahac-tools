Backup Retention (Prune) Simulator

Set a backup schedule (or paste your snapshot list) and the keep-last, hourly, daily, weekly, monthly, yearly and keep-within rules. The simulator runs the same rules through ports of Proxmox Backup Server, borg prune and restic forget, shows which snapshots each tool keeps and why, explains where the three disagree, and writes the matching command for each tool.

Backups

Backup days

"Every N hours" starts again at the first backup time each day, like cron's */N. Missed days (YYYY-MM-DD, comma-separated) show how days without a backup are skipped by the counts.

Paste the output of proxmox-backup-client snapshot list, borg list or restic snapshots, or plain timestamps. The simulator reads the last date and time on each line; times without Z or an offset are read in the time zone below. Nothing leaves your browser.

PBS, borg and restic all sort snapshots into hours, days, weeks, months and years by local time, so the time zone matters around midnight. "After every backup" is the usual setup; with Proxmox Backup Server it can keep different month-end snapshots than one prune over all backups.

Retention rules

Leave a rule empty (or 0) to turn it off. Type -1 or unlimited for no limit: borg and restic support it, Proxmox Backup Server does not. keep-within exists in borg and restic only.

      How the simulator works

      • Ported from source. Each column runs a port of that tool's own prune code: Proxmox Backup Server 4.2.8 (pbs-datastore/src/prune.rs), BorgBackup 1.4.5 (prune_split() and prune_within()) and restic 0.19.1 (ApplyPolicy()). They are checked against the worked examples in each project's docs and against restic's own test data.
      • Weeks. All three use ISO 8601 weeks: Monday to Sunday, and the week that holds 1 January can belong to the year before or after.
      • Rule order. PBS and borg apply the rules in order (borg starts with keep-within) and do not count a period an earlier rule already covered. PBS counts a period as covered when any snapshot in it is kept, borg only when its newest backup is kept. restic applies every rule on its own and keeps a snapshot if any rule wants it.
      • Time zone. PBS uses the server's time zone, borg the time zone of the machine that runs borg prune, and restic the local time stored in each snapshot by the machine that made it. The simulator uses the zone you pick for all three.
      • Prune timing. "After every backup" replays every PBS prune run, because a snapshot PBS removed once cannot come back. For borg and restic one run after the last backup gives the same result, which the tests check on random schedules.
      • Not modelled. Protected snapshots, unfinished backups and borg checkpoints, several backup groups (PBS groups, borg --glob-archives, restic --group-by), restic --keep-tag and --keep-within-daily and the like, borg's minutely, secondly and quarterly rules, and borg 2.0, which is still in beta and has a reworked prune command.

      Sources: PBS pruning docs, borg prune 1.4, restic forget.
