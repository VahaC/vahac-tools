2. Content-Security-Policy

Report-Only sends Content-Security-Policy-Report-Only: browsers report what would be blocked but block nothing — the safe way to try a new policy on a live site.

    Adds report-uri and report-to to the CSP plus a Reporting-Endpoints header. You need something that accepts the JSON reports — a small endpoint of your own or a hosted collector.

    3. HTTPS, framing and sniffing

    Raise max-age in steps (5 minutes → 1 week → 30 days → 1 year) and check that nothing breaks in between.

    4. Permissions-Policy

    Switch off browser features your site never uses, so injected or embedded code cannot ask for them. Chromium-based browsers apply this header; Firefox and Safari ignore it for now.

    5. Cross-origin and clean-up

    COOP same-origin-allow-popups is a safe start. Set COEP only if you need cross-origin isolation (SharedArrayBuffer, precise timers): it can block third-party images and embeds.

        How to get the headers

        This page does not fetch sites for you: browsers hide most response headers from cross-origin requests (CORS), so a "check URL" button in a web page gives incomplete answers. Copy them yourself — it takes seconds:

        • Linux / macOScurl -sI https://example.com
        • Windowscurl.exe -sI https://example.com
        • BrowserDevTools → Network → reload → click the page → Headers → Response Headers → Raw

        Some servers answer HEAD requests (-I) with fewer headers than GET. For a GET, use curl -s -D - -o /dev/null URL (-o NUL on Windows); add -L to follow redirects.
